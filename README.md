## 一、痛点：网申为什么让人崩溃

一个应届生投 50 家公司，平均要重复填写 **30~60 分钟 × 50 = 25~50 小时** 的表单。而这些表单问的几乎是同一批问题：

- 姓名、性别、出生日期、手机、邮箱、政治面貌、籍贯、现居城市……
- 学校、专业、学历、起止时间、GPA、排名……
- 实习经历、项目经历、技能、获奖、证书……

**核心矛盾**：信息高度重复，但每个招聘系统都要你从头再填一遍。字号不统一、字段名千奇百怪（`姓名` / `Name` / `真实姓名` / `applicant_name`），还有各种下拉框、级联选择、日期控件。

简历本身早就写好了，却要用手再敲一遍——这是纯粹的浪费。

## 二、解决方案

**简历飞填**在你本地保存一份结构化简历，打开任意招聘官网点击一键填充，插件自动完成扫描 → 匹配 → 写入：

```
本地简历(存储一次)
        │
        ▼
  扫描页面表单元素
        │
        ▼
  规则引擎匹配字段(100+ 中英同义词) ──► 未命中？ ──► 可选：大模型推断
        │
        ▼
   人工确认匹配结果
        │
        ▼
  写值(input / select / textarea / 日期控件)
```

**关键设计取舍**：

| 决策 | 选择 | 原因 |
|------|------|------|
| 匹配策略 | 规则优先，AI 兜底 | 规则零成本、毫秒级、可解释；AI 只处理长尾 |
| 数据存储 | `chrome.storage.local` | 简历含身份证级敏感信息，绝不上云 |
| 填充方式 | 用户确认后写入 | 自动填错比不填更糟，保留人工把关 |
| 交互入口 | 页面内悬浮按钮 | 不打断原有操作流，无需切换标签页 |

## 三、核心卖点

| # | 卖点 | 说明 |
|---|------|------|
| 1 | **纯本地，零数据外泄** | 简历只存浏览器本地，默认不调用任何外部接口。对比云端简历库产品，隐私风险为 0。 |
| 2 | **零配置即可用** | 内置 100+ 中英文字段同义词库，装完填一次简历就能干活，不需要 API Key。 |
| 3 | **中英文双语识别** | 4 种 DOM 写法（标准 `label`、左右布局文字、`placeholder`、`select`）都能识别，外企 / 国内大厂通吃。 |
| 4 | **AI 可选增强** | 填上 DeepSeek Key 就升级为大模型语义匹配，不填也不影响使用——**不绑架用户付费**。 |
| 5 | **覆盖列表型字段** | 不只是姓名电话，教育 / 实习 / 项目 / 技能 / 获奖等**多段经历**同样能填，这是多数同类工具做不好的地方。 |
| 6 | **匹配结果可审阅** | 填充前展示「识别到 N 个字段 / 可填入 M 个」，逐条确认，不搞黑箱。 |
| 7 | **可自测可扩展** | 附带本地测试页 `test-form.html` 与 jsdom 端到端测试，字段库开源可改。 |

## 四、快速开始

### 安装（本地加载，30 秒）

所有 Chromium 内核浏览器通用（Edge / Chrome / 360 极速 / QQ 浏览器 / Brave）。

**Edge**

1. 地址栏打开 `edge://extensions/`
2. 打开右下角 **开发人员模式**
3. 点击 **加载解压缩的扩展**
4. 选择本项目文件夹
5. 完成 ✅

**Chrome**

1. 打开 `chrome://extensions/`
2. 打开右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择本项目文件夹

### 使用

1. **填一次简历**：点击插件图标 → **编辑简历**，或直接用 **导入 JSON**（可参考 `examples/resume-sample.json` 格式）。
2. **打开招聘官网**（如大厂校园招聘的网申页）。
3. **点页面右下角「一键填简历」** → 扫描 → 确认匹配结果 → 自动填充。
4. **人工核对后提交**。⚠️ 自动填充不能替代人工检查。

## 五、功能详解

### 支持识别的字段

| 模块 | 字段 |
|------|------|
| 个人信息 | 姓名、英文名、性别、出生日期、手机号、邮箱、籍贯、现居城市、政治面貌、身份证号等 |
| 求职意向 | 期望岗位、行业、城市、薪资、到岗时间、工作类型 |
| 教育经历 | 学校、专业、学历、起止时间、GPA、排名、主修课程 |
| 实习 / 工作 | 公司、岗位、时间、地点、工作描述 |
| 项目经历 | 项目名、角色、时间、技术栈、描述、链接 |
| 技能 | 技能名、熟练度 |
| 其他 | 获奖、证书、语言能力、自我评价 |

### 简历管理

- 选项页按模块编辑，支持新增 / 删除多段经历
- **导入 / 导出 JSON**（导入后自动保存）
- 一键清空

### 诊断能力

扫描过程分 4 步执行并实时显示进度（步骤 1/4 → 4/4）。出错时面板直接展示版本号、脚本加载状态、页面表单元素数量与错误详情——**不转圈、不假死**。

## 六、技术架构

```
┌─────────────────────────────────────────────────────────┐
│  页面上下文 (content script)                              │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐             │
│  │ 悬浮按钮  │──►│ matcher  │──►│  filler  │             │
│  │ 结果面板  │   │ 字段匹配  │   │  写值    │             │
│  └──────────┘   └──────────┘   └──────────┘             │
└────────────────────────┬────────────────────────────────┘
                         │ chrome.runtime / storage
┌────────────────────────▼────────────────────────────────┐
│  Service Worker (background.js)                          │
│  · 简历读写  · DeepSeek API 调用（可选）· 历史记录        │
└────────────────────────┬────────────────────────────────┘
                         │ chrome.storage.local
┌────────────────────────▼────────────────────────────────┐
│  本地存储：简历 JSON（不上传任何服务器）                   │
└─────────────────────────────────────────────────────────┘
```

### 关键技术点

| 问题 | 处理方式 |
|------|---------|
| React / Vue 受控组件赋值无效 | 用 `Object.getOwnPropertyDescriptor(proto,'value').set` 触发原生 setter，再派发 `input` / `change` 事件 |
| 大页面扫描卡顿 | 可见性预剪枝 + 同义词索引缓存 + 4 秒时间预算 |
| 中文标签被英文关键词抢占 | 权重函数对中文字符加权，中文标签优先 |
| 数组型简历路径（`education.*.school`） | 递归路径解析器，遇 `*` 遍历数组元素 |
| 扩展更新后已开页面失效 | 孤儿脚本检测，直接提示「请按 F5 刷新」而非静默失败 |

## 八、BD 与商业化

> 本节面向合作方与投资人，说明市场机会、变现路径与合作方式。

### 8.1 目标用户与市场规模

**核心用户**：应届毕业生（本科 / 硕士）、社招求职者、海投型求职者、外企 Applicant。

**市场判断**（*以下为经验判断，非精确统计数据，落地前需核实*）：

| 指标 | 判断 | 依据 |
|------|------|------|
| 年新增求职人口基数 | **千万级** | 高校毕业生规模已达每年 1200 万以上量级（以教育部最新公布为准） |
| 单用户网申表单数 | 20~100 份 | 应届生海投常态 |
| 单份表单耗时 | 30~60 分钟 | 含重复信息录入 |
| 可节省时间 | **10~40 小时/人** | 按 70% 字段自动化估算 |
| 付费意愿 | 中低，但**转化场景明确** | 求职周期短（3~6 个月）、痛感强、付费阈值敏感 |

**关键洞察**：求职是**短周期、强痛点、低复购**的场景。纯订阅制天花板有限，真正的价值在 **B 端（高校就业中心 / 招聘平台 / 人力资源服务商）**。

### 8.2 商业化路径

| 阶段 | 模式 | 说明 | 状态 |
|------|------|------|------|
| 免费层 | 基础填充 | 规则匹配、本地存储，永久免费 | ✅ 已实现 |
| 增强层 | 自带 Key 的 AI 匹配 | 用户自付 API 成本，我们不抽成 | ✅ 已实现（待接入） |
| 增值层 | 高级模板 & 批量管理 | 多套简历版本、投递记录追踪、岗位 JD 关键词优化 | 🔜 规划中 |
| **B 端** | **高校就业中心定制** | 校内宣讲、就业指导课程配套工具，按校授权 | 🔜 规划中 |
| **B 端** | **招聘平台 / ATS 集成** | 与招聘系统打通，候选人信息预填，提升投递转化率 | 🔜 规划中 |
| 开放能力 | 表单识别 API | 把「字段匹配引擎」开放为 API，供第三方表单产品调用 | 💡 构想 |

### 8.3 BD 合作方向

我们**不打算**做成又一个云端简历库。合作原则：**插件留在用户设备上，能力对外输出**。

**① 高校就业中心 / 就业指导机构**
- 合作形式：批量部署指导、就业讲座植入、定制字段模板
- 我方价值：降低学生网申耗时，提升投递完成率
- 对方收益：可量化的就业服务工具，提升就业指导满意度

**② 招聘平台 / ATS 厂商**
- 合作形式：表单结构适配、联合调试、白标合作
- 我方价值：降低候选人中途放弃率（长表单是流失重灾区）
- 对方收益：**投递完成率提升** —— 这是招聘平台的核心 KPI 之一

**③ 求职服务商 / 校招培训机构**
- 合作形式：打包进求职辅导课程 / 简历优化服务
- 我方价值：作为服务交付的提效工具
- 对方收益：差异化卖点、服务交付成本下降

**④ 内容创作者 / 求职博主**
- 合作形式：教程内容合作、联名版字段模板
- 我方价值：精准获客
- 对方收益：实用选题、粉丝粘性

**➄ 开源社区**
- 合作形式：字段库贡献、适配更多招聘网站
- 我方价值：同义词库是最需要众包的部分
- 对方收益：参与一个有真实用户的工具

### 8.6 风险与应对

| 风险 | 应对 |
|------|------|

## 十、隐私与安全

这是本项目的**第一条设计原则**。

- ✅ 简历数据**只存在浏览器本地**（`chrome.storage.local`），不上传任何服务器
- ✅ 不开 AI 功能时，**不发起任何外部网络请求**
- ✅ 无账号体系、无埋点、无遥测
- ✅ 全部源码开源，可自行审计
- ✅ 权限最小化：仅 `storage` + `activeTab`（页面注入需 `<all_urls>`）

**⚠️ 重要提醒**：仓库**不包含**任何真实简历数据。`resume-data.json` 已被 `.gitignore` 排除，示例文件 `examples/resume-sample.json` 为**虚构数据**。

### 接入 DeepSeek（可选）

1. 选项页 → **设置** → 开启「启用 AI 匹配」
2. 填入 [DeepSeek 开放平台](https://platform.deepseek.com/) 申请的 API Key
3. 未匹配字段将由大模型做语义推断

> 启用后，**未匹配的字段描述**会发送至 DeepSeek 接口。介意的话保持关闭，规则匹配已覆盖绝大多数常见字段。

## 十二、开发与测试

### 环境要求

- Node.js 18+（仅测试需要）
- Python 3.9+（仅 PDF 提取脚本需要）
- 浏览器：Edge / Chrome（Chromium 内核）

### 运行匹配引擎测试

```bash
npm install jsdom
cd resume-autofill-extension
NODE_PATH="$(pwd)/node_modules" node test-matcher.js
```

测试覆盖三项断言：

1. **字段识别覆盖率** —— 关键字段是否全部命中
2. **数组路径取值** —— 教育 / 实习 / 项目等列表字段能否取到值
3. **同义关键词消歧** —— 「期望城市」不被「现居城市」抢占

### 手动验证

直接双击打开 `test-form.html`，点击页面右下角悬浮按钮。测试页模拟 4 种 DOM 写法：

- 标准 `<label for>` 关联
- 左文字 / 右控件的表格布局
- 仅靠 `placeholder` 命名的输入框
- `<select>` 下拉选择

**测试页能填、真网站不能填** → 说明是该网站 DOM 特殊，提 Issue 附截图即可。

### 添加字段同义词

编辑 `lib/resume-schema.js`，在对应字段的 `synonyms` 数组里加词：

```js
name: {
  label: '姓名',
  synonyms: ['姓名', '名字', '真实姓名', 'name', 'full name', 'applicant name']
}
```

### 推送代码（备用通道）

部分 Windows 环境下 `git push` 会**静默失败**（exit 128、无任何输出），排查成本极高。本仓库提供一个基于 GitHub REST API 的推送脚本作为替代：

```powershell
# 预览将要上传的文件
powershell -File tools\push-via-api.ps1 -DryRun

# 实际推送
powershell -File tools\push-via-api.ps1 -Message "feat: 新增字段同义词"
```

前置条件：已安装 `gh`（`winget install GitHub.cli`）并完成 `gh auth login`。

该脚本会自动排除 `resume-data.json` 等含个人信息的文件，重复执行相同内容不会产生多余 commit。
